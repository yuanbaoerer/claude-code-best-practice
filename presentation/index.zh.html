专业使用与 vibe coding 的区别 — 在 TodoApp 上展示：

上下文窗口 & /compact

关键概念

Claude 有一个 上下文窗口 — 即它能记住多少对话的限制。每个提示、读取的文件和响应都会填满它。

什么会填满上下文

你的提示和消息

Claude 读取的每个文件

Bash 命令输出

Claude 自己的响应

/compact — 解决方法

> /compact

将对话历史压缩成摘要。Claude 从该摘要继续。

最佳实践

在上下文使用率达到 ~50% 时手动运行 /compact。不要等待自动压缩 — 你会失去对保留内容的控制。

/plan — 编码前先规划

试试这个

> /plan > Add user authentication to the TodoApp backend

没有 /plan

Claude 立即写代码

方法错误 — 重做一切

在真正开始工作前 50% 上下文就没了

有 /plan

Claude 以只读方式探索代码库

提出方案供你审批

从一开始就正确的方法

经验法则

对于涉及超过 2-3 个文件或需要架构决策的任务，始终从 plan mode 开始。

Plan Mode 实践

分步进行

# 第 1 步：进入 plan 模式 > /plan # 第 2 步：描述你想要什么 > Add pagination to the /api/todos endpoint # 第 3 步：Claude 探索并写出计划 #（读取 routes/todos.py，检查 models，提出方案） # 第 4 步：审查计划并批准 # Claude 然后执行批准的计划

TodoApp 优势

在 plan 模式中，Claude 在写一行代码之前就发现了你现有的 SQLAlchemy 分页模式 — 不需要重复造轮子。

提示词最佳实践

🎯
文件要具体"In backend/routes/todos.py" 而不是 "in the backend code"
🔎
描述问题，不只是修复"The API returns 500 when..." 而不是 "make it work"
📐
引用现有模式"Follow the pattern in routes/todos.py" 给 Claude 一个模板
🧩
一次只做一件事小而集中的请求比大提示得到更好的结果
✅
让 Claude 验证"Run pytest after making changes" 及早发现错误
📸
为 UI 问题提供截图一张图片胜过千言万语

项目记忆

级别：Medium — 让 Claude 记住你的项目、约定和偏好。

CLAUDE.md & /init

关键概念

CLAUDE.md 是一个在 每个会话开始时 Claude 读取的 markdown 文件。它是你项目的 Claude 使用手册。

创建它

> /init

TodoApp CLAUDE.md

# CLAUDE.md ## 项目 TodoApp monorepo：FastAPI 后端 + Next.js 前端。 ## 结构 - backend/routes/ — FastAPI 路由处理器 - backend/models/ — SQLAlchemy 模型 - frontend/components/ — React 组件 - frontend/lib/api.ts — API 客户端 ## 命令 - cd backend && uvicorn main:app --reload - cd frontend && npm run dev - cd backend && pytest ## 约定 - 后端：遵循 routes/todos.py 中的路由模式 - 前端：使用 Tailwind，将导航添加到 Sidebar.tsx - 始终为新端点添加测试

CLAUDE.md 应包含什么

应该包含

项目架构概览

构建和测试命令

关键文件位置

编码约定

遵循的常见模式

关键的注意事项

避免包含

完整的 API 文档

长代码示例

密钥或 API key

经常变化的信息

超过 150 行的内容

关键规则

保持 CLAUDE.md 150 行以内。更长的文件会稀释指令 — Claude 可能会忽略部分内容。使用 Rules 和 Skills 获取详细信息。

保持在 150 行以内

如果你需要更多空间

📄
使用 Rules将特定主题的指令放在 .claude/rules/*.md 文件中
📚
使用 Skills将领域知识放在 .claude/skills/ — 按需加载
🔗
引用文件指向文档而不是内联内容

层次结构

CLAUDE.md（始终加载，<150 行）→ Rules（路径范围，自动加载）→ Skills（按需加载，任意长度）。

Rules (.claude/rules/)

什么是 Rules？

模块化的、主题特定的指令在单独的 markdown 文件中。与 CLAUDE.md 不同，rules 可以 作用域到特定路径。

TodoApp 后端测试 Rule

# .claude/rules/backend-testing.md --- globs: ["backend/tests/**"] --- 编写后端测试时： - 使用 pytest 和现有的 conftest.py fixtures - 遵循 test_todos.py 中的模式： - 使用 FastAPI 的 TestClient - 使用工厂函数创建测试数据 - 断言状态码和响应体 - 每个测试后清理测试数据库 - 命名测试：test_{action}_{entity}_{scenario} - 始终测试成功和错误情况

当 Claude 处理测试文件时此 rule 才会激活 — 保持其他任务的上下文干净。

/memory & 记忆层次

试试这个

> /memory

在编辑器中打开你的 CLAUDE.md 记忆文件。在此处的更改在所有会话中持久化。

三个作用域（按顺序加载）

# 会话开始时全部合并： ~/.claude/CLAUDE.md # 全局 — 所有项目 .claude/CLAUDE.md # 项目 — 通过 git 与团队共享 .claude/CLAUDE.local.md # 本地 — 个人的，git 忽略

TodoApp 技巧

将你的 TodoApp CLAUDE.md 放在仓库根目录，以便整个团队共享。将个人偏好（编辑器、样式）放在 CLAUDE.local.md 中。

记忆最佳实践

📏
CLAUDE.md 保持在 150 行以内简洁、聚焦、高信号的指令
📂
使用 rules 处理细节.claude/rules/ 中的路径作用域 rules 提供针对性指导
👥
提交项目 CLAUDE.md团队通过 git 共享项目约定
🔒
使用 .local.md 处理个人偏好Git 忽略，不会影响队友
🔄
定期审查和精简过时的指令会造成困惑

第五部分

领域知识

级别：High — 可重用的知识，Claude 按需加载。

什么是 Skills？

关键概念

Skills 是包含 领域知识 的 markdown 文件 — 指令、模式或工作流，Claude 需要时可以加载。把它们想象成微手册。

为什么使用 Skills？

📚
渐进式披露知识只在相关时加载 — 不会膨胀每个会话
♻
可重用相同的 skill 可以跨 agents 和工作流使用
👥
可分享提交到 git — 你的整个团队都受益

Skills vs CLAUDE.md

CLAUDE.md = 始终加载，每个会话。Skills = 按需加载，相关时加载。对于仅在某些时候需要的知识使用 skills。

创建 Skills：TodoApp 前端

前端约定 Skill

# .claude/skills/frontend-conventions/SKILL.md --- name: frontend-conventions description: TodoApp frontend patterns and conventions --- # Frontend Conventions 创建或修改前端组件时： ## Sidebar Navigation - Add new page routes to frontend/components/Sidebar.tsx - Use the existing NavLink pattern with icon + label - Keep alphabetical order in the nav list ## Component Patterns - Use functional components with TypeScript - Import API functions from lib/api.ts - Follow TodoList.tsx as the reference component - Use Tailwind classes: bg-white, rounded-lg, shadow-sm ## API Integration - All API calls go through lib/api.ts - Use the existing fetch wrapper with error handling - Base URL: process.env.NEXT_PUBLIC_API_URL

Skill Frontmatter & 调用

Frontmatter 选项

📜
nameSkill 标识符（如果省略则使用目录名）
📝
description何时调用 — 帮助 Claude 自动发现 skill
🤖
model覆盖运行 skill 的模型
🔧
allowed-tools限制 skill 可以使用的工具
🔁
context: fork在隔离的子代理上下文中运行 skill 以处理复杂工作流

调用 & 执行模式

# 1. 手动：斜杠命令 > /frontend-conventions # 2. 自动：Claude 通过 description 字段发现 # （当任务匹配 description 时发生） # 3. 预加载：在 agent 的 frontmatter 中 skills: - frontend-conventions # 4. 可选隔离，用于重型工作流 context: fork

Skills 总结

它们是什么

带有领域知识的 Markdown 文件

位于 .claude/skills/

有 SKILL.md + 可选的 supporting 文件

如何使用

/skill-name — 手动调用

通过 description 自动发现

通过 skills: 预加载到 agents

# Skill 目录结构 .claude/ skills/ frontend-conventions/ SKILL.md # 主 skill 文件（必需） backend-patterns/ SKILL.md error-handling.md # 支持文件（可选）

第六部分

Agentic Engineering

级别：High — 了解你的代码库并遵循你的模式的定制 agents。

什么是 Agents？

关键概念

Agents 是 .claude/agents/ 中的 markdown 文件，定义了一个 自定义 Claude 角色，具有自己的工具、模型、技能和行为。

使用 Agents 的两种方式

作为主 Agent

替换你对话的默认 Claude。

$ claude --agent frontend-engineer

作为子代理

通过 Agent 工具在隔离上下文中生成。

Task( subagent_type="frontend-engineer" prompt="Add a settings page" )

前端工程师 Agent

没有 Agent

> add a settings page

Claude 创建的 pages/settings.tsx：

• 内联 CSS（没有 Tailwind）

• 直接 fetch 调用（忽略 api.ts）

• 没有侧边栏导航入口

与应用不契合的独立页面。

有 Agent

前端 agent 已经知道：

• 使用设计系统中的 Tailwind token

• 从 lib/api.ts 导入 API 函数

• 将路由添加到 Sidebar.tsx

• 遵循 TodoList.tsx 组件模式

与应用完美匹配的集成页面。

# .claude/agents/frontend-engineer.md --- name: frontend-engineer description: Frontend development following TodoApp conventions tools: Read, Write, Edit, Bash, Glob, Grep model: sonnet skills: - frontend-conventions --- You are a frontend engineer for the TodoApp. Always add new pages to the Sidebar navigation. Use the existing API client in lib/api.ts. Follow TodoList.tsx as your reference component.

后端工程师 Agent

没有 Agent

> add a tags feature

Claude 创建随机端点结构

与现有路由不同的错误处理

没有测试，没有模型验证

有 Agent

后端 agent 遵循现有模式：

• routes/todos.py 中的路由结构

• 类似 models/todo.py 的 SQLAlchemy 模型

• 匹配 test_todos.py 风格的测试

• 用于验证的 Pydantic schemas

# .claude/agents/backend-engineer.md --- name: backend-engineer description: Backend development following TodoApp patterns tools: Read, Write, Edit, Bash, Glob, Grep model: sonnet skills: - backend-patterns --- You are a backend engineer for the TodoApp. Follow the route patterns in routes/todos.py. Create SQLAlchemy models matching models/todo.py. Always add pytest tests for new endpoints. Use Pydantic schemas for request/response validation.

Agent Frontmatter

# .claude/agents/code-reviewer.md --- name: code-reviewer description: Reviews code for quality and best practices tools: Read, Grep, Glob model: sonnet color: green skills: - code-review memory: user --- You are a code reviewer. Check for security issues, performance problems, and suggest improvements. Review your memory for patterns you've seen before.

Agent 工具 & Skills

限制工具

# 只读 agent — 不能修改任何内容 tools: Read, Grep, Glob # 完全访问 agent tools: Read, Write, Edit, Bash, WebFetch # 仅研究 agent tools: Read, Grep, Glob, WebSearch, WebFetch

关键模式

Skills 提供 静态知识（做什么）。Agents 提供 执行上下文（如何做，使用哪些工具）。它们结合在一起很强大。

选择模型

🧠

⚡
sonnet速度和能力的良好平衡
🏎
haiku快速、便宜 — 非常适合简单、专注的任务

通过 Task 工具调用子代理

关键概念

子代理在 隔离的上下文 中运行 — 与主对话分开。它们完成工作，返回摘要，它们的上下文被丢弃。

# Claude 自动生成子代理，或者你可以要求： > Use the frontend-engineer agent to add a settings page # Claude 在内部使用 Agent 工具： Task( subagent_type="frontend-engineer", prompt="Add a user settings page to the TodoApp" )

命令 & 编排

命令是复杂工作流的入口点 — Command → Agent → Skills 模式：

# .claude/commands/add-feature.md --- description: Add a new feature to the TodoApp model: opus --- # Add Feature Command 1. Ask the user what feature to add (AskUserQuestion) 2. Invoke the backend-engineer agent for API work: - Task(subagent_type="backend-engineer", ...) 3. Invoke the frontend-engineer agent for UI work: - Task(subagent_type="frontend-engineer", ...) 4. 命令位于 .claude/commands/。用户将它们作为斜杠命令调用：> /add-feature

复杂工作流的完整架构模式：

+-----------------------------------------------+ | /add-feature (Command) | | Entry point — user invokes this | | | | | +----------+----------+ | | v v | | backend-engineer frontend-engineer | | (Agent) (Agent) | | | | | | backend-patterns frontend-conventions | | (Skill) (Skill) | +-----------------------------------------------+

为什么它有效

Commands = 入口。Agents = 编排。Skills = 领域知识。清晰分离，最大可重用性。

重要

Claude 在运行潜在危险的命令之前会请求许可。始终审查它将要做什么。

读取文件

创建文件

黄金法则

1️⃣
始终从 plan mode 开始对于任何非平凡的任务。在 Claude 写代码之前审查计划。
2️⃣
保持 CLAUDE.md 在 150 行以内更长的指令会被稀释。使用 skills 和 rules 获取细节。
3️⃣
在 ~50% 时手动 /compact不要等待自动压缩。保持对保留内容的控制。
4️⃣
每个子任务后提交小而频繁的提交。干净的回滚点。
5️⃣
一次只做一件事小而集中的请求比大提示得到更好的结果。
6️⃣
文件要具体"Fix the null check in backend/routes/todos.py line 42" 而不是 "fix the bug"。
