progressive disclosure — 仅在需要时向 AI 提供所需信息，而非一次性全部给出

orchestration — 像指挥带领乐队一样协调多个 AI 智能体

dumb zone — 当上下文过多时，AI 反而会变笨的区间

agentic workflows — 能自主规划、行动、检验并调整的多步骤 AI 工作流

harness — 包裹在模型周围的脚手架——文件、终端、工具——让聊天机器人变成真正的劳动者

compaction — 自动压缩旧对话，让 AI 持续工作而不触及记忆上限

context window — AI 的工作记忆——一次能"看到"多少内容，超出后早期细节会被遗忘

ralph wiggum loop — AI 在同一个错误的步骤里兜圈子，像个停不下来的迷茫孩子

MCP — 让 AI 连接外部工具（GitHub、Slack、数据库）的通用适配器

hooks — 在 AI 执行任何操作前或后自动运行的脚本

context rot — 对话拖得越久，早期细节越模糊，质量随之下降

prompt engineering — 组织提问方式让 AI 精确理解你的意图

AI slop — 看起来精美但毫无实质的敷衍 AI 输出

inference — 模型实际运行并生成答案的时刻。训练是模型学习的时候（很久以前，一次性的）。推理是模型此刻正在回答你

hallucination — AI 自信地编造听起来真实但实际虚假的信息

context bloat — 给 AI 塞入过多信息，导致它变慢并失去焦点

one-shot prompting — 给 AI 一个例子，要求它照着做

token burn — 在不必要的来回或冗长的提示中浪费宝贵的 AI"字数"

vibe coding — 用大白话描述你想要什么，指望 AI 完美实现

agentic engineering — 建立防护栏，让 AI 像可靠的队友而非赌博一样行事

Agent 配置字段（frontmatter）

字段 描述 由谁强制执行
name 推荐 唯一标识符——例如 weather-agent harness
description 必填 何时调用。使用 "PROACTIVELY" 实现自动调用 prompt
model haiku、sonnet、opus 或 inherit（默认）。weather-agent 使用 sonnet harness
tools 工具白名单。weather-agent 允许 WebFetch、Read、Write 等。 harness
skills 启动时预加载到 agent 上下文中的 skills——weather-agent 预加载 weather-fetcher harness
maxTurns agent 停止前的最大智能体轮数。weather-agent 使用 5 harness
memory 持久化记忆：user、project 或 local。weather-agent 使用 project harness
color 任务列表中的视觉颜色。weather-agent 使用 green harness

skills: 字段让 agent 与众不同。它在启动时将 any-skill 直接预加载到 agent 的大脑中——在 agent 收到任何指令之前。

Skill 配置字段（frontmatter）

大多数字段控制 skill 的加载方式和时机——由 harness 强制执行。只有 description 属于提示词领域。

字段 描述 由谁强制执行
name 推荐 显示名称和 /slash-command（默认目录名） harness
description 必填 何时调用——用于自动发现。写清楚。 prompt
argument-hint / 菜单中显示的自动补全提示（例如 [city-name]） harness
disable-model-invocation 设为 true 以防止 Claude 自动调用此 skill harness
user-invocable 设为 false 以从 / 菜单隐藏——仅作为背景知识 harness
allowed-tools 此 skill 激活时无需权限提示即可使用的工具 harness
model skill 激活时使用的模型：haiku、sonnet、opus harness
context 设为 fork 以在隔离的子智能体上下文中运行 skill harness

Claude 的大脑

这样想

想象 Claude 有一个大脑，装着它此刻意识到的所有内容——你的问题、它打开的每个文件、每个工具结果、它对你说过的每个字。如果一个想法不在大脑里，Claude 就无法使用它。就这么简单。

💬
你的消息 每个问题、澄清和跟进
📄
Claude 打开的每个文件 读了一份 500 页的 PDF？现在全都在大脑里了。
🔧
每个工具结果 网页搜索、命令输出、截图——全都保存在记忆中

要知道的两件事

1. 大脑是有限的。它能容纳大约 100 万个 token——约 75 万字。很大，但不是无限的。2. 大脑在每次对话结束时清空。当你开始新对话时，Claude 对上一次对话什么都不记得，除非你再次告诉它。

会话启动时加载什么

当你打开 Claude Code 的那一刻，某些东西会在你输入任何字之前进入 Claude 的大脑。其余的在一旁待命——只有在你真正需要时才加载。这叫做渐进式披露。

📋
CLAUDE.md —— 完整内容 常驻指令，每一行。启动时始终固定在大脑中。
🎓
Skills —— 仅描述 Claude 知道有哪些 skills 以及每个 skill 做什么——完整内容在实际调用 skill 时加载。
👤
Agents —— 仅描述 专家名册。完整系统提示词在 agent 被派遣时加载。

一句话总结

启动时只加载 skills 和 agents 的描述——其余按需获取。这就是渐进式披露。它让大脑保持轻盈。

📄 迷失在中间

by Nelson F. Liu · Stanford University · 2023

  1. 首因效应和近因效应有效。 上下文开头（Claude 首先看到的）和结尾（Claude 最近看到的）的信息获得高度关注。这些是安全区。
  2. 中间是笨区。 埋在长上下文中间的内容实际上会消失。模型拥有这些 token，但在生成过程中不会强烈加权它们。它在工作记忆中——但并没有真正被阅读。
  3. 实际启示。 将关键指令放在最顶部（在 CLAUDE.md 中）或靠近用户最近的消息。如果你的内容落在中间，更大的上下文窗口也无济于事。

这就是本演示一直在警告的「笨区问题」——现在你知道它从哪来了。
