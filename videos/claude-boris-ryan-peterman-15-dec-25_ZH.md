## 文字稿

[`0:02`](https://youtu.be/AmdLVWMdjOk?t=2) 模型发展太快了。如果你在 3 个月或 6 个月后再问我这个问题，我的答案会完全不同。这是 Boris Chney。他是 Claude Code 的创造者，前 Meta 首席工程师。我们谈到了塑造他职业生涯的一切。你能解释一下潜在需求吗？

[`0:17`](https://youtu.be/AmdLVWMdjOk?t=17) 我认为潜在需求是产品中最重要的原则。

[`0:22`](https://youtu.be/AmdLVWMdjOk?t=22) 你说有一些明显的文化差异，这很困难。

[`0:26`](https://youtu.be/AmdLVWMdjOk?t=26) 天哪，困难这种说法太轻描淡写了。这是一场噩梦。我们还谈到了 Claude Code 以及 Anthropic 现在正在发生什么。尽管 Anthropic 规模扩大了三倍，但由于 Claude Code，每位工程师的生产力增长了近 70%。不要为今天的模型构建。要为 6 个月后的模型构建。我推荐给每个人的技术书籍，对我作为工程师影响最大的是，你对与 Codex 和 OpenAI 竞争有什么看法？我想从你故事的开头开始，你在 Meta 晋升为高级工程师。你晋升背后的项目故事是什么？当时你在哪里？如果我没记错的话，项目是聊天和群组，这是一个让 Messenger 和 Facebook 更紧密的项目。实际上我在 Meta 最初做的几个项目都是关于 Messenger 和 Facebook 的。第一个是扎克伯格关于同步 Messenger 聊天和 Facebook 群组的想法。但这些项目有一些旨在将 Messenger 和 Facebook 更紧密地联系在一起。我认为动机是感觉这种公共空间的社交产品正在消失，事情正在转向聊天和这些更随意的实时空间。所以我们尝试了几个版本的产品，聊天和群组是成功的一个。我想当时是第三或第四个。我在 Facebook，我与 Messenger 合作很多，在组织上非常遥远。这是 Steve 的想法，他当时的 PM，我采纳了这个想法，我说好啊，让我们做这个。所以我开始写代码。很快就有了一些生命迹象。所以我要求更多的工程师加入。有三个工程师加入了。Shatambri、Crystal 和 Chaang。他们是第一批加入的工程师。然后我们得到了一些数据科学支持、设计支持。最初只是 web 端。后来也移动端了一些。是的，我认为我们只是证明了这个想法，你可以在 Facebook 群组里有聊天，这种产品可以工作。老实说有很多东西根本不工作。按照现代产品标准，这是一个超级简陋的体验。以前每个人都在 web 上构建，各种 bug 都是可以接受的。如今，我认为标准——视觉标准、质量标准——要高得多。产品增长了，我们团队这么小，每个人都得做所有事情。我记得我们没有用户研究员，所以我会在午餐时间去餐厅，我们有一个新功能，我们就给餐厅工作人员看这个功能，说嘿你能找到怎么打开聊天吗？有时候他们能找到，有时候找不到，这就是一种观察性的用户研究。所以你可以看到人们在特定情况下如何完成任务，你不要给他们太多提示。你想看到他们在哪里挣扎。他们理解了什么。我们这样做，然后我教会团队如何做这个。很快我们都在午餐时间去餐厅，开始打扰餐厅工作人员，作为代表用户，问这有没有意义？有趣的是，早期 Facebook 的文化让你作为工程师可以做的事情远不止写代码。例如，你在做 UXR。听起来你也做了一些设计，你还在教别人做设计。我认为这是 Facebook 文化中一个独特有趣的东西。我认为这非常重要，直到今天，在 Claude Code 团队——这是我现在的团队——我们真的优先考虑通才。我喜欢与通才合作。如果你是一个会写代码的工程师，但你也能做产品工作。你也能做设计。你有产品感。你想去和用户交谈。我喜欢和这种工程师一起工作。这实际上是我们现在所有职能的招聘方式。我们的产品经理会写代码，我们的数据科学家会写代码，我们的用户研究员也会写一点代码。我只是喜欢这些通才，我认为这就像我从一开始成长的方式，当我 18 岁经营我的第一个创业公司时，我得做所有事情，直到 Facebook，我在较小的公司工作，你得做所有事情，我觉得在大公司，你被迫进入某个特定的泳道，但这只是表面上的，因为什么是工程？它是一个非常狭窄的技能集，但你真正在做的是构建产品或构建基础设施，端到端完成这件事涉及的远不止写代码。在那个半年结束时我晋升了，下一个半年团队里的每个工程师都晋升了。在那些早期产品中，有一个概念——潜在需求——你提到了几次，听起来这是很多产品方向的推动力。你能解释一下潜在需求吗？

[`5:42`](https://youtu.be/AmdLVWMdjOk?t=342) 我认为潜在需求是产品中最重要的原则。如果你看 Facebook 的成功产品，每一个都有潜在需求的元素。例如，Marketplace，它来自一个观察：如果你看当时的 Facebook 群组，40% 的帖子是买卖东西。Facebook 群组不是为商业设计的，但人们用它来做这个。这很酷，你设计的产品可以被用户"黑客"使用，然后你看数据，看他们如何"滥用"它，然后围绕它构建产品。有 Facebook 群组，然后有买卖群组，这成功了，因为人们已经想在 Facebook 群组上买卖东西和做商业，然后 Marketplace 出现了。这只是人们已有意图的自然延伸。Facebook Dating 也很相似。观察是大约 60% 的个人资料浏览是异性之间不是朋友的。这种传统的互相"偷看"，这是证据表明这会成功。产品的原则是你永远无法让人们做他们还没做的事情。你能做的是找到他们已有的意图，然后引导他们让他们更好地利用这种意图，更容易地做他们想做的事。

## 主要主题

1. **潜在需求（Latent Demand）** — 产品成功的最重要原则，找到用户已有的意图并构建产品满足它

2. **跨组织协作** — 当组织有不同价值观时协作的困难，需要找到共同目标

3. **副业项目（Side Quests）** — 对工程师成长至关重要，培养好奇心和通才能力

4. **类型思维** — 从函数式编程学到的最重要的编程思维模式

5. **向下调级入职** — 降低期望带来的好处——更多探索空间和更强初始印象

6. **共同设计竞赛** — 解决技术分歧的创新方法，让两个团队独立设计然后比较

7. **取消功能（Unshipping）** — 如果功能使用率不够高就删除它，保持产品简洁

8. **信任与共识** — 领导者需要在行动和共识之间平衡

9. **Claude Code 的诞生** — 为 6 个月后的模型构建，而非今天的模型

10. **AI 编程的未来** — 从手动编码转向编排多个 Claude 代理
